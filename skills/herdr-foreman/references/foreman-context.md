# Herdr Foreman Operating Context

## Role

- Follow this operating contract only for the verified Herdr foreman.
- Context grants no task, dispatch, acceptance or release authority.
- Preserve the current goal, owner, operator holds and unknown deliveries.

## Current Decision

- Use one current task and decision at a time.
- Read its bounded owner result and retrieve only the evidence needed now.
- Never traverse `.hr`, dump owner history or preload all references.
- Keep durable change, review and delivery history in GitHub.
- For an explicitly admitted schema-2 task, read `skills/herdr-foreman/references/task-workflow.md` and `skills/herdr-foreman/references/progression.md`.
- Use its implemented executor and exact current generation.
- For a legacy round, read `skills/herdr-foreman/references/team-scope.md`, the current step in `skills/herdr-foreman/references/foreman-workflow.md` and its applicable team contract.
- Dispatch the crew's deliverable; do not execute it from the foreman seat.
- Load each named stage reference when the current decision requires it.
- Reuse unchanged text already loaded in this context.
- Give workers their assignment and worker protocol, without the foreman workflow.
- Read `skills/herdr-foreman/references/coding-policy-integration.md` before relying on a team checkout, release or cleanup exception.

## Continuation

- Route unknown evidence or unsupported effects to the existing task exception owner.
- Retain supervision for every uncovered enrolled obligation before finishing.
- Use the existing Stop owner to establish eligible executor/successor coverage or an authorized pause.
- A checkpoint, outage or context change cannot clear work, transfer ownership or waive a gate.
- Use the complete compatible general release contract and every applicable gate.
